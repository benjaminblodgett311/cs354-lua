Language Overview and History

What is Lua?

Lua is a lightweight, embeddable scripting language designed to be integrated into larger applications, especially those written in C or C++. It focuses on simplicity, portability, and speed.

Lua was created in the early 1990s at the Pontifical Catholic University of Rio de Janeiro (PUC-Rio) by Roberto Ierusalimschy, Luiz Henrique de Figueiredo, and Waldemar Celes. It has since been used in many production systems, including game engines and embedded tools.

Our Project Theme

Problem: fast languages like C and C++ are often verbose when you try to express higher level logic.

Our solution: keep C for performance and system access, and embed Lua to write concise, high-level logic. Lua runs inside the C program as a small, flexible scripting engine.

Key Lua Features

Lua provides several language features that make it attractive as an embedded, high-level partner to C.

Dynamic Tables

Lua tables unify arrays and maps into a single data structure, letting us mix numeric and string keys in the same object. 

t = {}
t[1] = "hello"
t["name"] = "Ben"

print(t[1])
print(t.name)

Closures

Functions can capture local variables and remember state between calls, giving us simple, functional-style abstractions. 

function make_counter()
    local n = 0
    return function()
        n = n + 1
        return n
    end
end

c = make_counter()
print(c())
print(c())

Coroutines

Coroutines let us pause and resume computations, which is useful for cooperative multitasking and scripting game logic. 

co = coroutine.create(function()
    print("step 1")
    coroutine.yield()
    print("step 2")
end)

coroutine.resume(co)
coroutine.resume(co)

Embedding Lua Inside C

Why Embed Lua?

C gives us control, speed, and access to the system. Lua gives us a compact syntax, dynamic structures, and faster iteration on logic. By embedding Lua:

  • C controls performance-critical code and integration with the OS.
  • Lua scripts express higher-level behavior and configuration.
  • We can change behavior by editing Lua code without recompiling C.

Project Focus

Our team demonstration program shows how a C host can:

  • Initialize a Lua state and load the standard libraries.
  • Define and call Lua functions from C.
  • Expose C functions to Lua as if they were built-in.

This illustrates how embedding Lua helps reduce verbosity in the high-level parts of an otherwise low-level, performance-oriented program.

Minimal C + Lua Embed Example

The program below creates a Lua state, runs simple Lua code, calls a Lua function from C, and registers a C function that Lua can call. 

#include <stdio.h>
#include <lua.h>
#include <lualib.h>
#include <lauxlib.h>

static int c_add(lua_State *L) {
    double a = luaL_checknumber(L, 1);
    double b = luaL_checknumber(L, 2);
    lua_pushnumber(L, a + b);
    return 1;
}

int main(void) {
    lua_State *L = luaL_newstate();
    luaL_openlibs(L);

    luaL_dostring(L, "print('Hello from Lua!')");

    luaL_dostring(L,
        "function add(x, y)\n"
        "    return x + y\n"
        "end"
    );

    lua_getglobal(L, "add");
    lua_pushnumber(L, 10);
    lua_pushnumber(L, 32);
    lua_call(L, 2, 1);
    printf("Lua result: %.0f\n", lua_tonumber(L, -1));
    lua_pop(L, 1);

    lua_pushcfunction(L, c_add);
    lua_setglobal(L, "c_add");

    luaL_dostring(L,
        "print('C add result:', c_add(5, 7))"
    );

    lua_close(L);
    return 0;
}

Build and Run: C Program with Embedded Lua

  1. Install Lua development packages on Debian/Ubuntu:
sudo apt install lua5.4 liblua5.4-dev
  1. Locate the Lua include directory:
dpkg -L liblua5.4-dev | grep lua.h
  1. Compile the program (example path shown for Lua 5.4):
LUA_INCLUDE=/usr/include/lua5.4
gcc embed.c -I"$LUA_INCLUDE" -o embed -llua5.4 -lm -ldl
  1. Run the program:
./embed

Translators and Installation

Lua is distributed as source and is typically compiled as a library plus a small standalone interpreter. Below are practical installation steps for our environment.

Lua Interpreter and Libraries (Linux)

  1. Install the interpreter and development files on Debian/Ubuntu:
sudo apt install lua5.4 liblua5.4-dev
  1. Verify that Lua is available:
lua -v

Lua on Other Platforms

  • Windows and macOS users can download source or binaries from the official Lua site and follow its build instructions.
  • On macOS with Homebrew, Lua can be installed with a single command such as brew install lua.

Using Lua as an Embedded Translator

  • Include Lua headers from the Lua development package.
  • Link against the Lua library when compiling C programs.
  • Use the Lua C API to load scripts, run code, and move values between C and Lua.

Language Comparison

Our main design question was how to balance speed and verbosity. The table below compares Lua with some representative languages we care about in this project.

Aspect Lua C Python JavaScript
Primary role in our project Embedded scripting language Host language, performance core General scripting / prototyping Web and general scripting
Execution model Interpreted/bytecode VM Compiled to native code Interpreted/JIT Interpreted/JIT
Typing Dynamically typed Statically typed Dynamically typed Dynamically typed
Typical verbosity Compact syntax, few core constructs Verbose for high-level logic Readable but larger runtime Flexible but tied to larger runtimes
Embedding into C Designed for embedding, small library N/A (host) Possible but heavier integration Possible via engines, more overhead
Use cases Game scripting, configuration, plugins Systems programming, performance-critical code Data science, scripting, automation Web apps, browser scripts, servers
Balance of speed and expressiveness Fast enough for most logic, concise, and easy to embed in C Very fast, but high-level code can be verbose Expressive, slower, larger runtime Expressive, usually JIT-accelerated, heavier engines

In our project, we keep C where we need raw speed and low-level control, and we write higher-level behavior in Lua. This directly targets our original problem: we do not want to give up performance, but we also do not want every piece of high-level logic to be written in verbose C.
